# React2Kuikly 步骤6：代码验证和完善

## 目标

最终验证和完善转换结果，确保功能完整性和代码可编译。

## 前置条件

- 已完成步骤 5，所有 Kuikly 代码文件已输出到 `$OUTPUT_DIR` 目录下

## 验证流程

按优先级从高到低执行。

### 步骤 6.1：逻辑功能完整性验证

确保转换后的代码**完整保留**了原始 React Native 代码的所有业务逻辑。

**逐文件对比源代码和生成代码**，重点检查：

- **条件分支完整性**：所有 `if/else`、`switch/when`、三元表达式的分支是否**全部**转换，不得遗漏任何分支
- **循环与迭代逻辑**：`for`、`map`、`forEach` 等循环逻辑是否完整保留，边界条件是否一致
- **状态管理逻辑**：所有 `state`、`props` 的读写和更新逻辑是否完整迁移
- **事件处理链路**：所有事件回调（点击、滚动、生命周期等）是否完整转换，回调中的业务逻辑是否保留
- **异常/边界处理**：`try/catch`、空值判断、默认值处理等防御性代码是否保留
- **数据流转逻辑**：组件间的数据传递、回调通知、全局状态访问等是否完整
- **⚠️ 外部依赖组件行为一致性**：对照步骤 5.1 分析报告中记录的外部组件映射关系，验证 Kuikly 组件的选择是否正确反映了外部组件的实际行为（如：使用了 `ViewPager` 的 `TabView` 是否正确映射为 `SliderPage`，而非简单的 Tab 切换）。如有疑问，直接读取外部依赖源码确认

> 发现遗漏的逻辑必须**立即补全**，不得标记为"已知问题"跳过。

**进度更新**：
```bash
bash skill/scripts/update-progress.sh --pageName "$PAGE_NAME" --step "6.1" --status "completed" --nextAction "开始步骤6.2：编译检查"
```

### 步骤 6.2：编译检查

**必须**使用 Kuikly MCP 提供的 `analyze_files` 工具对生成的代码进行编译检查：
- 传入生成代码的文件路径，工具会自动找到项目根目录和对应模块进行编译
- 检测编译错误并逐一修正，**循环执行直到编译通过**
- 如果 `analyze_files` MCP 工具不可用，则使用其他可用的编译检查手段（如 `kotlinc` 命令行），**不得直接跳过编译检查**

**进度更新**：
```bash
bash skill/scripts/update-progress.sh --pageName "$PAGE_NAME" --step "6.2" --status "completed" --nextAction "步骤6完成，全部转换流程结束"
```
