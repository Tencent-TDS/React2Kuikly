# React2Kuikly 步骤5：生成 Kuikly 代码

## 概述

本 skill 负责将 React Native 源代码分文件、渐进式地转换为 Kuikly 代码。按依赖关系从底层到顶层依次转换，确保转换的精确性和可控性。

## 前置条件

- 已完成步骤 1-4，统一转化知识库 `react2kuikly/[页面名]/cache/knowledge-cache.md` 已准备完成（包含框架知识、组件知识、业务知识、架构规范和 checklist）

## 转换流程

### 步骤 5.1：分析文件结构和依赖关系

**目标**：全面分析 React Native 源代码的文件结构以及外部依赖文件，理解文件间的依赖关系。

**执行脚本**：
```bash
bash skill/scripts/analyze-file-structure.sh --pageName "$PAGE_NAME" --sourceDir "[React Native源代码目录]" --outputDir "$OUTPUT_DIR" --aliasDir "[@ 别名映射的实际目录]"
```

**执行步骤**：

#### 5.1.1 识别源目录内文件

扫描源目录下的所有文件，按类型分类：

1. 识别主页面文件（包含页面级组件/路由入口的文件）
2. 识别子组件文件，区分基础组件和复合组件
3. 识别工具类、常量文件、API 文件
4. 识别样式文件（不需要单独转换，仅供组件转换时引用）

#### 5.1.2 识别外部依赖文件并分类处理

> ⚠️ **此步骤必须执行，不可跳过。** 外部依赖的分类和处理策略直接影响转换质量。

1. **扫描所有 import/require 语句**，收集引用路径指向**源目录之外**的文件（排除 `node_modules` 下的第三方 npm 包）
2. **对外部依赖进行分类**，区分**组件类**和**方法/变量类**：
   - **组件类外部依赖**：被引用的导出内容是 React 组件（class 组件或函数组件）
   - **方法/变量类外部依赖**：被引用的导出内容是函数、常量、工具方法等非组件内容
3. **组件类外部依赖**作为独立文件纳入转换计划   
4. **方法/变量类外部依赖不需要读取源码**，只读取和转化被引用的方法或者变量，不要整个文件转化


#### 5.1.3 分析依赖关系

基于 5.1.1 和 5.1.2 的结果，构建完整的依赖关系图：

1. 分析源目录内文件之间的引用关系和依赖链
2. 外部依赖纳入依赖关系图，标注引用方向和引用内容
3. 识别循环依赖问题
4. 输出依赖关系图（文本格式）

#### 5.1.4 确定转换优先级并生成转换计划

根据依赖关系图，确定文件的转换顺序：

1. 先转换被依赖的底层文件（数据模型、常量、工具类）
2. 再转换中间层组件（包括需要整文件转换的外部依赖组件）
3. 最后转换页面级组件

**输出文件**（缓存到 cache 目录）：

- `react2kuikly/[页面名]/cache/analysis-report.md` - 分析报告
- `react2kuikly/[页面名]/cache/conversion-plan.md` - 转换计划

`analysis-report.md` **必须包含**以下章节：
1. **文件清单和文件类型**（文件名、类型，外部依赖也一起纳入清单，区分组件类和方法/变量类的转化方式）
2. **依赖关系图**

`conversion-plan.md` **必须包含**以下章节：
1. **转换顺序**（按批次从底层到顶层排列所有需要转换的文件，外部依赖也一起纳入转换计划中）
2. **不转换的文件**（样式文件、入口文件等）

> **缓存复用**：如果上述两个文件已存在，说明步骤 5.1 已执行过，可提示用户选择直接跳到步骤 5.2，或重新生成。

**进度更新**：
```bash
bash skill/scripts/update-progress.sh --pageName "$PAGE_NAME" --step "5.1" --status "completed" --nextAction "等待用户确认转换计划后开始步骤5.2"
```

#### 暂停：等待用户确认转换计划

> **必须执行**：步骤 5.1 完成后，**必须暂停并展示转换计划给用户确认**，用户确认后才能继续步骤 5.2。

**展示内容**：
1. 从 `conversion-plan.md` 中提取**转换顺序**（按批次列出所有输出文件及其来源）
2. 从 `conversion-plan.md` 中提取**不转换的文件**（及原因）

**确认要点**：
- 文件拆分方式是否合理
- 输出文件命名是否符合预期
- 不转换的文件列表是否正确
- 转换批次顺序是否合理

**用户操作**：
- 用户确认 OK → 继续步骤 5.2
- 用户要求修改 → 根据反馈修改 `conversion-plan.md` 和/或 `analysis-report.md` 后重新展示确认
- 用户也可以直接手动编辑 `conversion-plan.md` 文件后告知继续

### 步骤 5.2：逐文件转换

**断点续转**：查看 `progress.md`获取当前转换进度，若已经完整了部分转换则根据完成进度进行断点续转
1. 执行 `bash skill/scripts/check-progress.sh --pageName "$PAGE_NAME"` 查看已完成的文件列表
2. 对比 `conversion-plan.md` 中的转换计划，自动跳过已完成的文件，只转换剩余文件

**目标**：根据依赖关系`react2kuikly/[页面名]/cache/analysis-report.md`和转换计划`react2kuikly/[页面名]/cache/conversion-plan.md`，按如下转换规则**依次转换**，转换完成一个文件**更新进度后**再进行下一个，确保每个文件的转换完整且准确。

**转换规则**：
1. **代码分析**：
   - 逐行分析单个 React Native 源代码文件
   - 理解代码结构、变量定义、函数调用
   - 识别业务逻辑和 UI 逻辑

2. **不同文件处理**：
   - **样式文件跳过**：Kuikly 没有独立的样式文件，样式直接写在组件属性上。转换组件文件时根据其引用的样式自动内联即可。
   - **外部依赖组件处理**：若外部组件被完整引用，可整文件转换；若只被引用了部分，则只转换被引用的部分。

3. **知识库`knowledge-cache.md`应用**：
   - 严格按照知识`knowledge-cache.md`进行转换，不使用知识库信息之外的属性
   - 对于 React Native 源码中存在但知识库中没有的属性或逻辑，添加 `// TODO` 注释标记

4. **单文件逻辑验证**（每个文件转换后立即执行）：
   - 逐一对照原始 React Native 源码，确认当前文件的所有业务逻辑已完整转换
   - 检查条件分支、循环、回调等逻辑是否有遗漏
   - 验证数据流和状态管理的完整性

5. **业务 Checklist 检查**（每个文件转换后立即执行）：
   - 读取 `knowledge-cache.md` 中的 checklist 部分（来自业务 Skill 的 `CHECKLIST` 配置）
   - 发现不符合 checklist 的代码**直接修正**

**文件级进度更新**：
> ⚠️ **每完成一个文件的转换，必须立即更新文件级进度**，防止 token 超限导致中断后无法断点续传。

```bash
# 每完成一个文件转换后立即执行
bash skill/scripts/update-progress.sh --pageName "$PAGE_NAME" --step "5.2" --status "file_done" --fileInfo "<源文件名> -> <输出文件名>"
```

**步骤 5.2 全部完成后更新步骤级进度**：
```bash
bash skill/scripts/update-progress.sh --pageName "$PAGE_NAME" --step "5.2" --status "completed" --nextAction "开始步骤5.3：架构整理与目录规范化"
```

### 步骤 5.3：架构整理与目录规范化

**目标**：在所有文件转换完成后，统一审查和整理代码架构，确保目录结构、引用关系和代码风格的一致性。

**执行内容**：

1. **目录结构审查**：
   - 读取 `knowledge-cache.md` 中的示例代码，确认其目录组织方式（如页面入口、组合组件、ViewModel、数据模型、工具类等分别放在哪个目录下）
   - 检查步骤 5.2 生成的文件是否都在正确的目录下
   - 如有文件位置不符合示例代码的目录规范，执行迁移

2. **引用关系修正**：
   - 检查所有文件间的 import 路径是否与实际目录结构一致
   - 修正因文件迁移导致的引用路径变更

**进度更新**：
```bash
bash skill/scripts/update-progress.sh --pageName "$PAGE_NAME" --step "5.3" --status "completed" --nextAction "步骤5完成，可继续步骤6：代码验证和完善"
```

## 工具脚本

1. `analyze-file-structure.sh` - 文件结构分析
2. `update-progress.sh` - 进度更新
