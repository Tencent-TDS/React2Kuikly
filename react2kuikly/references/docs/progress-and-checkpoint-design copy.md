# react2kuikly 方案 — 进度记录与关键节点存档询问设计分析

---

## 一、设计背景

### 1.1 核心问题：AI Agent 对话的"失忆"和"失控"

react2kuikly 是一个 **6 步、多子步骤的复杂代码转换流程**（步骤1→2→3→4(4.1~4.5)→5(5.1~5.3)→6(6.1~6.2)），单次转换涉及大量文件和长时间执行。这导致两个关键问题：

- **对话中断导致进度丢失**：AI Agent 的上下文窗口有限，长流程中对话可能因 token 超限、网络中断等被截断，所有中间状态全部丢失
- **自动化流程缺乏人工把控点**：整个流程涉及多个决策点，如果 Agent 全程自动执行，错误会被层层传递和放大，到最终才暴露，返工成本极高

### 1.2 业务特点

- **流程长**：6 个主步骤 + 10+ 子步骤，单次完整执行 token 消耗巨大
- **中间产物有复用价值**：关键字缓存和知识库缓存构建成本高，重复生成浪费严重
- **决策点需要人工判断**：关键字提取是否准确、转换计划是否合理，Agent 无法完全自行判断

---

## 二、设计方案

整体设计分为两套互补的机制：**进度记录系统** 和 **关键节点存档询问机制**。

### 2.1 进度记录系统

每个页面转换任务有一个独立的进度文件 `react2kuikly/[页面名]/cache/progress.md`，采用 **Markdown 格式**（便于 AI Agent 直接阅读理解），包含以下关键字段：

- **当前状态**：一句话描述整体进度
- **Checkbox 列表**：`[x]`/`[ ]` 标记每步完成状态，支持嵌套子步骤
- **下一步操作**：明确指示 Agent 接下来应执行什么
- **最后更新**：时间戳，便于判断是否为过期任务

**写入机制**：每个步骤完成后，通过 `update-progress.sh` 脚本统一写入进度（更新 checkbox、状态字段、时间戳、下一步操作）。

**恢复机制**：对话中断后，新对话中读取 `progress.md` 解析当前状态和下一步操作，配合 `check-progress.sh` 扫描工作目录已有文件，即可从中断点继续。

### 2.2 关键节点存档询问机制

流程中设计了 **3 个阻塞询问点** 和 **3 个非阻塞缓存复用点**：

**阻塞询问点**（必须等待用户确认）：

| 节点 | 位置 | 设计目的 |
|------|------|---------|
| **前置校验** | 流程开始前 | 检查业务 Skill 和目标 package 是否齐全，缺少则停止 |
| **关键字确认** | 步骤 4.5 | 关键字决定知识库内容，错误关键字→错误知识→错误代码，此处纠错成本最低 |
| **转换计划确认** | 步骤 5.1 完成后 | 文件拆分和转换顺序直接影响代码质量，用户可判断架构合理性 |

**非阻塞缓存复用点**（提示用户选择跳过或重新生成）：

| 节点 | 缓存文件 | 行为 |
|------|---------|------|
| **知识缓存检查** | `knowledge-cache.md` | 存在→可跳到步骤5；不存在→继续步骤4 |
| **关键字缓存检查** | `project-keywords.md` | 存在→可跳过4.1~4.3直接到4.4 |
| **分析报告缓存** | `analysis-report.md` + `conversion-plan.md` | 存在→可直接跳到5.2 |

## 三、收益分析

### 3.1 进度记录系统的收益

- **跨对话断点续传**：对话中断后读取 `progress.md` 即可从中断步骤继续，无需从头重来，节省 50%~80% 的 token 和时间
- **中间产物缓存复用**：`knowledge-cache.md` 构建需大量搜索和合并，缓存后可在多次转换尝试间复用
- **可观测性**：用户随时可查看 `progress.md` 了解当前进度
- **页面隔离**：每个页面有独立的 cache 目录和进度文件，多页面并行互不干扰

### 3.2 关键节点询问的收益

- **错误前置拦截**：在"错误放大器"之前设置卡口，关键字错误和计划错误在传播前就被拦截
- **降低返工成本**：步骤4.5拦截关键字错误零浪费，否则步骤6才发现需回退重做步骤5
- **灵活跳过**：缓存复用点允许用户跳过已完成步骤，迭代调优场景下极其高效

---

## 四、总结

- **进度记录**解决"状态持久化"——让无状态的 AI Agent 具备跨会话的任务记忆能力
- **关键节点询问**解决"决策质量控制"——在错误传播链的关键节点设置人工卡口，以最低成本拦截错误

两者配合，使原本需要"一气呵成"的复杂转换流程，变成了**可暂停、可恢复、可分段迭代**的可控流程。
